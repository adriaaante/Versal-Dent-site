1. `get_file_metadata(fileId=<ID>)` — проверить mime/размер.

## Конфиденциальность лица на клинических фото (обязательно)

Если на фото «до/после» видно **лицо пациента** — перед вставкой убираем
узнаваемость. Приоритет: **фокус на работе (улыбка/зубы), а не на лице**.
Способ по умолчанию — **кадрируем до зоны улыбки** (нос-подбородок),
глаза и верх лица вне кадра. Если клиника уже закрыла глаза плашкой —
всё равно кадрируем до улыбки, плашку в кадр не тащим. Кроп — в том же
формате **4:3 1200×896**, затем `apply-watermark.py`. **Оригиналы в
`_originals/` тоже храним уже обезличенными** — узнаваемого лица в
репозитории быть не должно. (Альтернатива для фронтальных портретов —
сильное размытие глаз; но кроп до улыбки надёжнее и выглядит как
полноценный dental «до/после».)

## Кроп «до/после» — заполнять кадр без полей (обязательно)

Снимок 4:3 `1200×896` должен заполняться **целиком**: по краям (особенно
снизу) НЕ должно быть фона/рамки/тёмной полосы. В лайтбоксе фото
показывается во всю высоту (`height:auto`), поэтому любая запечённая в
картинку полоса вылезет под фото — лечится **кропом, не CSS**. Частая
причина — исходник это телефонный скрин с чёрной (статус-бар) или
бежевой рамкой: кадрируем **строго внутри лица**, не задевая рамку.

«До» и «После» сняты по-разному (пациент чуть крупнее/мельче, выше/ниже),
поэтому **каждое фото кадрируем отдельно**, но к ОДНОЙ посадке: рот по
центру, одинаковый зум, глаза вне кадра. Проверка перед сохранением:
верхний и нижний ряды пикселей кропа — кожа/зубы, а не фон/рамка. Эталон —
`rustamov-prosthetics-before/after` (кропы подобраны независимо, чтобы оба
заполняли кадр без полос).

## Галерея «Ещё фото работы» (доп. снимки в лайтбоксе)

У работы в `portfolio.js` можно задать поле `extra` — массив доп. фото,
которые показываются под «до/после» в лайтбоксе и открываются крупно в
просмотрщике (как и сами «до/после» — клик по фото). Формат снимков тот
же (4:3 1200×896, водяной знак, обезличено).

```js
extra: [
  { src: '../assets/img/portfolio/<имя>.webp', caption: 'Подпись' },
  { src: '../assets/img/portfolio/<имя>.webp', caption: '...', graphic: true }
]
```

`graphic: true` — для клинических кадров (кровь/хирургия): миниатюра
заблюрена с предупреждением «Клинический кадр», а **картинка грузится
только после клика** (по согласию — бережно к посетителю и не светит
графику поисковику до взаимодействия). Логика — в `assets/js/portfolio.js`
(`openLightbox` → блок галереи, `openShotViewer`), стили — `.pf-shot*` и
`.pf-shot-viewer` в `assets/css/styles.css`. Достаточно **одного**
графичного кадра на кейс, не перегружаем.

Реальные работы в портфолио: у `kilasoniya` — кейс «Кабинетное
отбеливание» (фото пациента от 15.08.2026, `kilasoniya-whitening-*`),

## Фото врачей — единый стиль (ОБЯЗАТЕЛЬНО)

Все портреты врачей на сайте **в одном формате**: силуэт вырезан из
исходного фона и поставлен на фирменный **айвори-градиент** (верх
`#ECE2CF` → низ `#F6F0E5`), кадр **4:5**, голова и плечи, лицо по центру
с небольшим отступом сверху. Эталон — `drobkova` / `rustamov`. Нельзя оставлять «сырое» фото с чужим фоном — оно выбьется
из ряда карточек.

**Как добавить/обработать фото врача**:
```
python3 scripts/prepare-doctor-photo.py <исходник.jpg> <slug> [--zoom 1.0] [--top 0.05]
```
Скрипт сам убирает фон (rembg, модель `birefnet-portrait`; первый запуск
качает ~970 МБ модель), ставит на айвори-градиент и режет в 4:5. На выходе
**четыре** файла (как у всех врачей): PNG + WebP в двух размерах.
- `assets/img/doctors/<slug>.png|.webp` — 480×600 (полная);
- `assets/img/doctors/<slug>-thumb.png|.webp` — 256×320 (миниатюра карточки).
**`<img>` на страницах ссылаются на `.webp`** (в ~15 раз легче), PNG
остаётся для `og:image` (совместимость с мессенджерами). Страницы:
`doctors/index.html`, блок врачей на `index.html`, `doctors/<slug>.html`.

⚠️ Если `rembg` в окружении нет (в CCR-контейнере его обычно нет, а модель
~970 МБ качать долго) — фон снимаем через MCP Higgsfield: `media_upload` →
curl PUT → `media_confirm` → `remove_background` (media_type `image`) →
скачать PNG. Скрипт видит готовую прозрачность (>5 % пикселей с alpha<10)
и берёт вырезку как есть. Так сделано фото Киласонии (23.08.2026).

`--zoom` — доля ширины кадра под силуэт (по умолч. `1.0`). Для фото с
пышными волосами / в полный разворот ставь больше (`1.1–1.35`), чтобы
**лицо совпало по размеру** с остальными карточками. Уже подобрано:
`hachatryan 1.12`, `kendabaeva 0.98`, `savchuk 1.30`, `kilasoniya 1.16`
(с `--top 0.04`). После генерации
**сравни миниатюру глазами** с существующими — посадка лица должна совпасть.

Дополнительно доводим фото под эталон (drobkova/rustamov):
яркость субъекта ≈ L130, тёплый тон (R>G>B), и **одежда должна читаться

## Дипломы и сертификаты врачей (сканы) — как добавлять

Документ врача = **две картинки**, готовит `scripts/prepare-doc.py`:

```
python3 scripts/prepare-doc.py скан.jpg --slug drobkova --name ordinatura \
    --caption "Диплом об окончании ординатуры, «Ортодонтия», 2016" \
    [--rotate 90] [--crop 2,3,2,4]
python3 scripts/asset-version.py
```

- `<slug>-<name>-thumb.webp` (420 px, ~20 КБ) — **только она в HTML**,
  `loading="lazy"` + width/height (без скачков вёрстки);
- `<slug>-<name>.webp` (до 1500 px) — грузится **только по клику**, вес
  страницы и Core Web Vitals не страдают (это фактор ранжирования);
- оригинал → `assets/img/docs/_originals/` (не деплоится).

Скрипт сам вставляет карточку в блок `<ul class="docs" data-docs>` на
странице врача и добавляет документ в JSON-LD `Person → hasCredential`
(сигнал экспертности для YMYL-тематики). Клик открывает светлый
просмотрщик (`.docview` в styles.css + блок в конце `main.js`); без JS
ссылка открывает скан в новой вкладке. `--rotate` разворачивает скан
**в самом файле** — CSS-поворотами не пользуемся, иначе миниатюра и
просмотрщик расходятся.

⚠️ Публикуем только то, что подтверждено документом. Курсы и «сертификаты
систем», о которых нет скана, на страницах врачей не пишем — до
15.08.2026 там висели выдуманные строки (Damon System Certified, курс
Star Smile, 3Shape Trios), их заменили данными из реальных дипломов.

⚠️ **Правило владельца (19.08.2026): чего нет в документе — на странице не
пишем**, и пустых блоков после этого остаться не должно.

⚠️ **Уточнение владельца (01.09.2026): истёкшие документы ПОКАЗЫВАЕМ —
они показывают опыт.** Сертификаты специалиста Дробковой (2016, 2020) и
свидетельство об аккредитации Хачатрян (2018/2020) вернулись карточками.
Условие одно: рядом должен быть виден действующий допуск, а в блоке
«Образование» — честная строка вида «срок действия завершён, допуск
подтверждён периодической аккредитацией 2025 года». Так документ работает
на историю квалификации и никого не вводит в заблуждение. Следит скрипт `python3 scripts/doctor-credentials.py`
(`--check` для проверки): он выкидывает `<li>` с TODO-комментарием внутри,
а если список опустел — убирает и заголовок, оставляя подсказку в
HTML-комментарии. Так страница выглядит завершённой, а не «недозаполненной».
Пример: сертификат специалиста Дробковой 2016 года действовал 5 лет и
истёк — строку сняли, ждём свидетельство об аккредитации.

⚠️ **Карточкой публикуем не всё (решение 24.08.2026).** Скан идёт в галерею,
если документ что-то говорит пациенту о лечении: система брекетов, ВНЧС,
детский приём, съезды, международные конгрессы. Семинары про управление
практикой (например, Ormco «Мыслить иначе — двигаться к успеху», 2014) и
дубли одной темы остаются **строкой в списке курсов, без карточки** — иначе
галерея превращается в склад. Сертификат на добрачную фамилию (OHi-S 2023,
«Кристина Титушина») тоже без карточки: чужая на вид фамилия на видимом
документе смущает посетителя.

⚠️ **Длинная галерея сворачивается до двух полных строк.** JS считает по
вёрстке, сколько карточек помещается в строку сетки (она `auto-fill`, колонок
от ширины экрана), оставляет две строки, остальным ставит `hidden` и добавляет
кнопку «Показать все документы (N)». Пересчёт на `resize`. Ряд всегда полный:
на 3 колонки видно 6, на 4 — 8. **На телефоне (≤640px) документы идут
горизонтальной лентой** — там все карточки в одной «строке», поэтому ничего не
прячется и кнопки нет (владелец, 24.08.2026: «зачем на телефоне „показать все“,
если там карусель»). Скорость при этом не страдает: у элементов с `hidden`
картинки с `loading="lazy"` не загружаются — на десктопе тянется 8 миниатюр
вместо 20, на телефоне 3. **В разметке видны все документы** (класс/атрибут
ставит только JS), поэтому поисковик получает полный список, и JSON-LD
`hasCredential` тоже полный. Стили — `.docs > li[hidden]` и `.docs-more`
в конце styles.css.

У Дробковой сейчас **20 карточек** (из 23 подтверждённых курсов).

⚠️ **Знак клиники на сканах документов (владелец, 01.09.2026).** Документы
врачей — такой же контент клиники, как фото портфолио, поэтому на них
стоит маленький полупрозрачный знак. Правила:

- знак ставит сам `prepare-doc.py` (функция `stamp`), руками ничего
  накладывать не надо; **оригиналы в `_originals/` остаются чистыми** —
  знак появляется уже после их сохранения, поэтому повторные прогоны его
  не наслаивают;
- угол выбирается **по картинке**, а не жёстко: у дипломов верх занят
  гербом и шапкой, у сертификатов низ — подписями и логотипами
  организаторов, поэтому скрипт считает «занятость» правого верхнего и
  правого нижнего угла и ставит знак в свободный;
- знак **перекрашивается в эспрессо `#2C2620`** и ставится с прозрачностью
  0.34: родной серебристый знак на белой бумаге просто растворялся. На
  тёмных сертификатах (бывают чёрные) скрипт сам делает знак белым;
- размер 13% короткой стороны, отступ 3,2%: документ должен читаться
  целиком — это его главная задача, знак не должен спорить с текстом.

Поменялись правила отрисовки (размер знака, формат миниатюр) — все
документы пересобираются из чистых оригиналов одной командой:

```
python3 scripts/docs-rebuild.py            # все документы
python3 scripts/docs-rebuild.py drobkova   # только одного врача
```

Размер миниатюр при этом не меняется (420×315), поэтому HTML и JSON-LD
трогать не нужно.

⚠️ **Ссылки на сканы несут версию** (`...webp?v=1a2b3c4d`): reg.ru кеширует
webp на месяц, и без хеша пересобранный скан (новый знак, поворот) у
прежних посетителей не обновлялся. `docs-rebuild.py` проставляет версии
сам; после ручного `prepare-doc.py` прогнать `python3
scripts/docs-version.py` (есть `--check`).

⚠️ **Ориентация сканов проверяется скриптом (урок 24.08.2026).** Сертификат
Twicare у Дробковой уехал на прод лежащим на боку: партию сканов я смотрел
«пачкой» на контактном листе и не разглядел. Теперь после `prepare-doc.py`
обязательно:

```
python3 scripts/docs-orientation-check.py [<slug>]   # код 1, если что-то боком
```

Скрипт считает, вдоль какой оси идут строки текста (поля 15% срезаются —
рамки сканов перебивают сигнал), и ловит повороты на 90°/270°: на 20 сканах
Дробковой поймал 20 из 20 намеренно повёрнутых без ложных срабатываний.
⚠️ Переворот на **180°** (текст вверх ногами) эта метрика не отличает —
поэтому скрипт заодно собирает контактный лист
`assets/img/docs/_originals/_orientation-sheet.png` (в .gitignore): на него
надо посмотреть глазами, это одна картинка на всех врачей.

Миниатюры документов приводятся к **4:3 на белом** (вписыванием, не
обрезкой — документ должен читаться целиком): разные по формату дипломы
и сертификаты встают в ряд ровно.

## Workflow пушей

Разработка — на сессионной ветке (см. инструкции сессии). После коммита
пушим в фичевую ветку: `git push -u origin <сессионная-ветка>`.

⚠️ **ПРАВИЛО ВЫКАТКИ (владелец, 10.08.2026): пуш в `main` = автодеплой
на прод через GitHub Actions. В `main` пушим ТОЛЬКО после явного
подтверждения владельца («выкатывай»): сделал правки → показал → дождался
«ок» → `git push origin <фичевая>:main`.** Это заменяет прежнюю
договорённость «пушить в обе ветки сразу» (была актуальна при ручном
деплое). PR не создаём, если не попросили.

⚠️ **Уточнение владельца (26.08.2026): `main` — единственная актуальная
ветка, расхождений быть не должно.** Практика:

- **Материалы, которые на прод не попадают** (`_materials/`, `scripts/`,
  `CLAUDE.md`, README/BRAND) — пушим в `main` сразу, не дожидаясь
  «выкатывай»: rsync их исключает, сайт от такого пуша не меняется.
- **Всё, что видно посетителю** (html, css, js, картинки сайта) — прежний
  порядок: показал → дождался «ок» → `git push origin <фичевая>:main`.
- После «ок» ветку и `main` **оставляем на одном коммите** (у Венеции —
  плюс дефолтная `claude/venetia-dental-website-vr6cb6`), чтобы не искать
  потом, где свежее.
